# Tradic PoC

Interactive electricity-trading proof of concept. Mocked Emsys-like VPP, Meteologica-like forecast ensembles and a thin Periotheus-like ETRM **generate** telemetry, prices, bids and settlements at runtime. Parameters live in `interactive/config/sim.yaml`. Connection secrets stay in environment variables (compose `environment:`), not in the YAML.

The same compose starts **Postgres, MinIO, the Iceberg catalog (JDBC on Postgres), Trino, the API, and the UI**. Do not also start `trading-dbt/docker-compose.yml` — both bind host port **5433**.

## Quick start

```bash
docker compose -f docker-compose.interactive.yml up --build
```

| Service | URL | Notes |
| --- | --- | --- |
| Streamlit UI | http://localhost:8501 | One WebSocket per session; PICASSO 4s setpoints in the live panel |
| FastAPI | http://localhost:8000/docs | REST + WebSocket `/ws` |
| PostgreSQL | localhost:5433 | `dbt_user` / `dbt_password`, database `iceberg_dbt` |
| MinIO | http://localhost:9011 | `minio_user` / `minio_password`, bucket `iceberg-data` |
| Trino | http://localhost:8082 | Catalog `iceberg`, schema `raw` |

1. Click **Start** (sim clock begins at the YAML `clock.sim_start`, default 2026-06-02 12:00).
2. Select `WT-EE-N-01` and click **Send down-regulation**.
3. Wait until the 15-minute ISP closes (~15 wall seconds at default speed).
4. Open report **mart_curtailment_compensation** and click **Refresh reports (dbt run)**.
5. Lost energy and mFRR-down compensation appear for the curtailed asset.

### PICASSO 4s setpoints

With the clock running, the live panel shows **PICASSO 4s** from the session WebSocket (`/afrr/recent` also lists them). Setpoints are written to `trading.afrr_activations` about every 4 wall seconds.

### Rainflow bid rejection

Place an `ELERING_mFRR_UP` bid at a few EUR/MWh on the BESS portfolio (`Wind_EE_North`). Wear cost from `bess.replacement_eur` / Wöhler knobs in YAML is the floor: cheap bids come back `REJECTED` (or `REPRICED` near the floor). SoH is on the asset table.

### Iceberg live rows

After the sim has been running (or click **Flush Iceberg now**):

```sql
-- Trino
SELECT asset_id, event_ts, active_power_kw, ingested_at
FROM iceberg.raw.emsys_telemetry
ORDER BY ingested_at DESC
LIMIT 20;
```

Or `GET http://localhost:8000/iceberg/telemetry`. Compaction: `POST /iceberg/maintain`.

## Where parameters live

| Kind | Location |
| --- | --- |
| Physics, markets, ISP, Iceberg flush, asset overlays | `interactive/config/sim.yaml` |
| Hosts, ports, DB/S3 credentials | environment / compose `environment:` |
| Asset master (nameplate, lat/lon, membership) | Postgres `trading.assets` (dbt fixture in `02-test-data.sql`); physics overlays in YAML |
| Trading tapes / prices / telemetry | **not in source** — generated by the simulators |

Override the YAML path with `SIM_CONFIG`.

## Local run without Docker (Postgres already on 5433)

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r interactive/requirements.txt
export PYTHONPATH=.
export PGHOST=localhost PGPORT=5433 PGUSER=dbt_user PGPASSWORD=dbt_password PGDATABASE=iceberg_dbt
uvicorn interactive.backend.main:app --host 0.0.0.0 --port 8000
# other terminal
TRADING_API_URL=http://localhost:8000 streamlit run interactive/ui/streamlit_app.py --server.address 0.0.0.0
```

Unit tests (no database):

```bash
PYTHONPATH=. pytest interactive/tests -q
```
