# Tradic PoC

Interactive electricity-trading proof of concept. Mocked Emsys-like VPP, Meteologica-like forecast ensembles and a thin Periotheus-like ETRM **generate** telemetry, prices, bids and settlements at runtime. Parameters live in `interactive/config/sim.yaml`. Connection secrets stay in environment variables (compose `environment:`), not in the YAML.

The same compose starts **Postgres, MinIO, the Iceberg catalog (JDBC on Postgres), Trino, the API, and the UI**. Do not also start `trading-dbt/docker-compose.yml` — both bind host port **5433**.

## Quick start

```bash
docker compose -f docker-compose.interactive.yml up --build
```

| Service | URL | Notes |
| --- | --- | --- |
| Streamlit UI | http://localhost:8501 | One WebSocket per session; PICASSO 4s setpoints in the live panel |
| FastAPI | http://localhost:8000/docs | REST + WebSocket `/ws` |
| PostgreSQL | localhost:5433 | `dbt_user` / `dbt_password`, database `iceberg_dbt` |
| MinIO | http://localhost:9011 | `minio_user` / `minio_password`, bucket `iceberg-data` |
| Trino | http://localhost:8082 | Catalog `iceberg`, schema `raw` (`iceberg.namespace` in YAML) |

`GET /health` returns `{"status":"ok"}`. `GET /state` lists generated assets from Postgres (`WT-EE-N-01`, `WT-EE-N-02`, `WT-EE-N-12`, `PV-EE-S-01`, `BESS-EE-01`), `speed_factor` from `clock.default_speed_factor` (60), and `afrr_period_seconds` from `clock.afrr_period_seconds` (4.0).

Operator walkthroughs are in [Sample scenarios](#sample-scenarios) below.

## Where parameters live

| Kind | Location |
| --- | --- |
| Physics, markets, ISP, Iceberg flush, asset overlays | `interactive/config/sim.yaml` |
| Hosts, ports, DB/S3 credentials | environment / compose `environment:` |
| Asset master (nameplate, lat/lon, membership) | Postgres `trading.assets` (dbt fixture in `02-test-data.sql`); physics overlays in YAML |
| Trading tapes / prices / telemetry | **not in source** — generated by the simulators |

Override the YAML path with `SIM_CONFIG` (compose sets `SIM_CONFIG=/app/interactive/config/sim.yaml`). The process reads YAML **once at startup**; edit the file, then `docker compose -f docker-compose.interactive.yml restart backend`.

## Sample scenarios

These steps use the running API. The Streamlit UI calls the same endpoints (sidebar **Start** / **Send down-regulation** / **Place / accept bid**, **Refresh reports (dbt run)**, **Flush Iceberg now**).

### 1. Start the stack

```bash
docker compose -f docker-compose.interactive.yml up --build
```

Wait until `trading-poc-postgres`, `trading-poc-minio`, `trading-poc-trino`, `trading-poc-backend`, and `trading-poc-ui` are up. Then:

```bash
curl -sS http://localhost:8000/health
curl -sS http://localhost:8000/state
curl -sS -X POST http://localhost:8000/sim/start
```

Expected: health `{"status":"ok"}`. After start, `GET /state` has `"running": true`. Sim time starts from `clock.sim_start` on a fresh database (`2026-06-02T12:00:00`); an existing volume keeps the persisted `trading.sim_clock` row. Clock speed is `clock.default_speed_factor` sim minutes per wall second (60). `clock.isp_minutes` is 15, so one ISP is about 15 wall seconds at that speed.

### 2. Down-regulate `WT-EE-N-01` and read `mart_curtailment_compensation`

`WT-EE-N-01` is a 3000 kW wind asset in portfolio `Wind_EE_North`. If `setpoint_limit_kw` is omitted, the API caps at 20% of nameplate (600 kW). The example uses 400 kW for 20 sim minutes (`duration_minutes`, default 20).

```bash
curl -sS -X POST http://localhost:8000/market/down-regulation \
  -H 'content-type: application/json' \
  -d '{"asset_id":"WT-EE-N-01","setpoint_limit_kw":400,"duration_minutes":20}'
```

Expected: JSON `event_id` like `DR-WT-EE-N-01-…`; that asset’s `control_mode` is `EXTERNAL_CONTROL` and `setpoint_limit_kw` is 400. Wait until `GET /state` `recent_events` includes `Settled ISP … (curtailed)` (next `clock.isp_minutes` boundary). Then:

```bash
curl -sS -X POST http://localhost:8000/dbt/run \
  -H 'content-type: application/json' \
  -d '{"full_refresh":false}'
curl -sS 'http://localhost:8000/reports/mart_curtailment_compensation?limit=20'
```

Expected: dbt `status` `ok` (45 models on Postgres). Report rows include `asset_id`, `lost_energy_mwh`, `compensation_eur`, `clearing_price_eur_mwh`. `WT-EE-N-01` has `lost_energy_mwh` > 0 for the curtailed interval. Compensation is lost energy times the generated `ELERING_mFRR_DOWN` price (`markets.mfrr_down_price_eur_mwh` when curtailed). The 2026-06-01 rows are the dbt fixture afternoon in `02-test-data.sql`, not the live sim tape.

### 3. Watch 4s PICASSO

With the clock running (`POST /sim/start`), PICASSO writes aFRR setpoints every `clock.afrr_period_seconds` (4.0) wall seconds onto `BESS-EE-01` unless that asset is in `EXTERNAL_CONTROL`. Amplitude is `nominal_kw * markets.afrr_setpoint_frac` (0.4).

```bash
sleep 9
curl -sS http://localhost:8000/afrr/recent
```

Expected: `"period_seconds": 4.0` and a growing `rows` list. Each row has `asset_id` `BESS-EE-01`, `setpoint_kw`, `direction` (`UP`/`DOWN`), `price_eur_mwh` from `markets.afrr_price_eur_mwh` (15.0), and `wall_ts`. The UI **PICASSO 4s** metric is the same WebSocket `type=afrr` payload. Rows are also inserted into `trading.afrr_activations`.

### 4. Reject a cheap mFRR bid via Rainflow

`BESS-EE-01` is in `Wind_EE_North`. Wear floor uses `bess.replacement_eur` (250000), Wöhler knobs (`wohler_n_ref`, `wohler_dod_ref`, `wohler_w`), and `clock.isp_minutes` as the cycle duration. A bid below that floor is `REJECTED`; within 5% above the floor it is `REPRICED`.

```bash
curl -sS -X POST http://localhost:8000/market/bids \
  -H 'content-type: application/json' \
  -d '{"portfolio_id":"Wind_EE_North","market_code":"ELERING_mFRR_UP","price_eur":5,"volume_mw":1,"accept":true}'
```

Expected: `"order_status":"REJECTED"`, `"price_eur":5.0`, and `wear_floor_eur_mwh` well above 5 (generated from the YAML knobs, not a fixed tape). A `price_eur` of 10000 on the same body returns `CONFIRMED`. SoH is on `GET /state` under the BESS asset (`soh_percent`, `degradation_cost_eur`).

### 5. Flush and query Iceberg

The backend buffers generated telemetry and aFRR rows and appends to Iceberg namespace `iceberg.namespace` (`raw`) every `iceberg.flush_rows` (50) or `iceberg.flush_seconds` (60), or on demand. Postgres writes stay regardless.

```bash
curl -sS -X POST http://localhost:8000/iceberg/flush
curl -sS 'http://localhost:8000/iceberg/telemetry?limit=20'
```

Expected: flush JSON `"status":"ok"` and `"rows"` > 0 (`telemetry_rows` / `afrr_rows`). Start the clock first so the sink has buffered samples. `GET /iceberg/telemetry` runs Trino:

```sql
SELECT asset_id, event_ts, active_power_kw, ingested_at
FROM iceberg.raw.emsys_telemetry
ORDER BY ingested_at DESC
LIMIT 20;
```

That GET returns at least one row with those columns. Compaction endpoint: `POST /iceberg/maintain`. Postgres telemetry remains on `GET /telemetry/history`.

### 6. Change a static parameter and see the sim pick it up

YAML is loaded once at process start (`interactive/backend/config.py`). Compose mounts `./interactive` and sets `SIM_CONFIG=/app/interactive/config/sim.yaml`.

1. Set `clock.afrr_period_seconds` from `4.0` to `8.0` in `interactive/config/sim.yaml`.
2. `curl -sS http://localhost:8000/afrr/recent` still shows `"period_seconds": 4.0` until restart.
3. `docker compose -f docker-compose.interactive.yml restart backend`
4. After `/health` is ok, `GET /afrr/recent` shows `"period_seconds": 8.0`.
5. Put `4.0` back and restart again so the default PICASSO period stays 4 seconds.

The same restart applies to other knobs (`wind.cut_out_ms`, `bess.replacement_eur`, `markets.da_price_mean_eur_mwh`, `iceberg.flush_rows`, asset overlays under `assets:`). Prices and telemetry after restart are still generated, not replayed from a file.

## Local run without Docker (Postgres already on 5433)

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r interactive/requirements.txt
export PYTHONPATH=.
export PGHOST=localhost PGPORT=5433 PGUSER=dbt_user PGPASSWORD=dbt_password PGDATABASE=iceberg_dbt
uvicorn interactive.backend.main:app --host 0.0.0.0 --port 8000
# other terminal
TRADING_API_URL=http://localhost:8000 streamlit run interactive/ui/streamlit_app.py --server.address 0.0.0.0
```

Unit tests (no database):

```bash
PYTHONPATH=. pytest interactive/tests -q
```
